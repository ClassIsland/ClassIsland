## 修复：科目分组「分组标题颜色」在分组设置里强调色偏深

现象：档案编辑 → 科目 → 分组信息里的「分组标题颜色」色块显示为 #00B294（偏深），
而课表选课里同一分组的默认标题颜色是正常的高亮强调色（用户描述为 #21FFE0）。

### 实测数据（关键证据）
- 用户 Windows 强调色基色 = **#00B294**（注册表 `HKCU\Software\Microsoft\Windows\DWM\AccentColor`，
  ABGR 0xFF94B200；`AccentColorMenu`、`Explorer\Accent\AccentPalette[3]` 同为 #00B294）。
- `Explorer\Accent\AccentPalette`（BGRA，8 项）=
  [#67FFEE, **#21FFE0**, #00D3B1, **#00B294**, #009B7E, #00664A, #00361B, #68768A]
  → 用户看到的 #21FFE0 是「深色外观下使用的浅色变体」，不是基色。
- 应用设置：`ColorSource = 2`（跟随系统强调色）、`Theme = 3`（跟随系统 → 深色）。
- 截图逐像素采样：色块 = #00B294（与 `SystemAccentColor` 相同）。
- FluentAvalonia 探针（`AccentTextFillColorPrimaryBrush`）：
  基色 #00B294 → Default/Light = #007D68，Dark = #03FFD5；
  基色 #21FFE0 → Default/Light = #00CAAD，Dark = #A3FFF2；
  `SystemAccentColor` 在三种变体下都等于基色。

### 根因
`AccentColorPicker` 用 `Application.ActualThemeVariant` 去查 `AccentTextFillColorPrimaryBrush`。
主题设为「跟随系统」时 `Application.ActualThemeVariant` 恒为 `ThemeVariant.Default`，
按主题字典查会命中**浅色**字典，于是在深色外观下取到深色变体（偏深）。
而分组标题走的是可视化树上的 `DynamicResource`，用的是当前真实外观（深色）→ 亮色变体，两者不一致。

### 修改
- `ClassIsland/AccentColorPicker.cs`
  - `GetCurrentAccentColor()` 改为按「真正生效的外观变体」解析 `AccentTextFillColorPrimaryBrush`
    （`RequestedThemeVariant` 非 Default 时直接用它，否则回落到
    `PlatformSettings.GetColorValues().ThemeVariant`），保证色块与分组标题渲染一致；
    失败时退回 `AccentFillColorDefaultBrush` → `AccentColorSource` 兜底。
  - 新增私有 `GetEffectiveThemeVariant(Application)`。
  - 新增 `using Avalonia.Platform;`（`PlatformThemeVariant`）。
- 之前工作区里「改用 `SystemAccentColor`」的做法会显示基色 #00B294（即用户看到的偏深色），已弃用。

### 复用提示
- 调试 FluentAvalonia 强调色资源可用 `.codex-debug/fluent-accent-probe`（源码已删，仅剩 bin/obj）；
  该程序把 `#FF21FFE0` 作为 `CustomAccentColor` 硬编码，可直接二进制替换 DLL 内同长度的
  UTF-16 字符串来改测其它强调色。

## 第三渲染点修复：「课表 → 编辑科目」分组标题颜色偏暗（已完成）

- **根因（像素级验证）**：`ListBoxItem:disabled` 的 `Opacity` 默认为 **0.5**（FluentAvalonia 主题样式），
  而分组标题项靠 `IsEnabled="{Binding !IsGroupHeader}"` 禁止选中 → 整项被降到 50% 不透明度。
  `#67FFEE` 与深色背景 `#282D30` 各半混合 = `#47968F`，正是用户看到的「偏暗的深绿」。
  用户自定义色的「主科」同理：`#FF4343` 混成 `#932F2A`（暗红）。
- **为什么只有 ListBox 出问题**：`ComboBoxItem:disabled` 的 `Opacity` 天然是 **1**（不降透明度），
  所以换课窗口、列表视图的科目下拉框一直是对的。
- **修法**（三处 `<ListBox.Styles>` 内新增）：
  ```xml
  <Style Selector="ListBox:not(:disabled) ListBoxItem:disabled">
      <Setter Property="Opacity" Value="1" />
  </Style>
  ```
  - `ClassIsland/Views/ProfileSettingsWindow.axaml`（列表视图「编辑科目」+ 周视图「编辑科目」）
  - `ClassIsland/Controls/ScheduleDataGrid/ScheduleDataGridCellControl.axaml`（课表单元格 Popup）
  - **必须带 `ListBox:not(:disabled)` 限定**：周视图的 ListBox 自身有
    `IsEnabled="{Binding !ViewModel.SelectedClassInfo.IsEmpty}"`；若只写 `ListBoxItem:disabled`，
    则「未选中课程」时整个列表不再变暗（实测 Opacity 由 0.5 变 1），属可见回归。
- **验证**：`ClassIsland.csproj` 与 `ClassIsland.Desktop.csproj`（Debug，`--no-restore`、
  `-p:GeneratePackageOnBuild=false`）均 0 错误。
- **`2.json` 实况**：`主科` = `#ffff4343`（用户自定义红）、`副科` = `''`（跟随强调色）、
  分组由 3 个变为 2 个（`小四门` 已被删除）。→「主科是红色」不是 bug，只是被压暗了。

### 探针新技能：用 AvaloniaRuntimeXamlLoader 验证选择器- `Selector.Parse` / `Selectors.Parse` 在 **Avalonia 11.3.13 都不存在**（编译报 CS0117）。
  正确入口：`AvaloniaRuntimeXamlLoader.Parse<Styles>(xaml, assembly)`，需引用
  `Avalonia.Markup.Xaml.Loader.dll`；走的是与仓库 XAML 完全相同的管线。
- 关键结论：**选择器语法在编译期就会被校验**（Loader.dll 内有 `AvaloniaXamlIlSelectorTransformer`
  与 `XamlSelectorsTransformException`）。故意写坏 `ListBoxItem::bogus` 会抛
  `XamlSelectorsTransformException: Unable to parse selector`。
  → 因此「`dotnet build` 通过」本身就是选择器合法的证据。
- 探针坑：`new Style()` 不给 `Selector`（null）**永远不会匹配**，会让对照组静默失效（本次踩过），
  必须显式赋选择器。
