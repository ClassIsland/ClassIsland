# ClassIsland acceptance 执行流程

本文件约定项目验收顺序；运行方法以 [PROJECT.md](PROJECT.md) 为准，证据、轮次和交付合同以 [acceptance 技能](../skills/acceptance/SKILL.md) 为准。

## 判断本次是否需要运行

1. 明确用户要验收的行为与平台，先检查当前任务已有的报告、原始证据、发布链接和 `.acceptances/`。仍有效的证据保留原始来源，不为分享报告重新启动应用。
2. 纯文档、指令或不改变产品行为的工具配置跳过产品验收，只做相关质量检查。Gitlink 同步、已有报告发布等情形按技能处理。
3. 确需新增验收时，先运行 `lh acceptance preflight --json`，记录模式与报告语言；配置不变时可复用同轮已取得的结果。`local` 渲染本地报告；已登录状态的鉴权错误不能静默降级为未登录。

## 环境与计划

1. 执行负责人读取适配文档、两份项目日志及本次所需的技能参考；同一版本的源码事实和探测结果明确由一人取得，再向其他执行者交接。
2. 按 [技能的委派规则](../skills/acceptance/references/delegation.md) 安排新验收的 runner 和首轮 checker；技能要求的能力或独立检查不可用时按其降级规则如实披露。
3. 根据 `PROJECT.md` 检查已有进程、设备、数据目录、工具链及权限。执行负责人只管理本轮拥有的环境；有界面目标时先确认真实界面驱动与捕获能力，不从命令输出推定其可用。
4. 按 [报告规范](../skills/acceptance/references/report.md) 的 `new_round` 约定分配新的 `.acceptances/<交付标识>/<时间戳>-<轮次>/`，先确保 `.acceptances/.gitignore` 存在且内容为 `*`，再写入产物。不要覆盖历史轮次，不在适配目录存放报告或截图。
5. 编写用户能够接受或拒绝的行为检查，保存 `plan[]` 与 `requiredEvidence`。编译、测试、静态检查仅作为报告中的质量验证叙述，不作为验收项。首轮先完成技能要求的计划审查，再操作产品。
6. 按本机 CLI 帮助取得支持的结构与参数。离线模式使用 `lh acceptance run validate <roundDir> --json`；发布模式在执行前用与正式发布相同的目标参数运行 `lh acceptance run ingest <roundDir> --dry-run --json`。离线校验不能代替远程语言与计划归属检查。

## 执行与证据检查

- 记录目标源码版本、构建命令和结果、实际运行程序或 APK、设备、数据及权限前提。每项观察只描述已执行动作、实际结果和影响判断的限制。
- 原始证据随执行保存到本轮 `assets/`，同时更新 `result.json`。每个附件写清内容与证明的结果；详细日志放在附件，避免堆入观察字段。
- 修改已有界面的文案、布局或样式时，同一场景保留旧实现与新实现的前后对比，并记录两边构建来源；既有用户证据满足条件时直接复用。
- 截图与录像由指定检查者实际查看；文件存在、解析成功或文字描述不是检查。录像按技能记录章节，声音交付保留音频。
- 首轮按技能完成一次最终报告与证据审查；修复轮仅补验受影响行为，保留有效证据与来源。已发布轮次不可变，修复写入同一验收的新轮次。
- 逐项检查 `requiredEvidence` 的每种类型是否齐全。缺失必需类型时不能通过，并明确未完成覆盖；无法操作的项目记录阻塞原因。

## 报告、收尾与交付

按技能生成 `result.json`、`proposal.md` 和需要的叙述报告，检查校验输出和警告。下面命令中的目录及需求均为本次实际值；目标关联参数沿用该验收已有身份：

```powershell
$roundDir = '<本轮目录>'
lh acceptance run validate $roundDir --json
lh acceptance run render $roundDir --requirement "整体验收的一句话目标" --json
```

以上渲染路径用于 `local` 或用户明确要求本地的场景；发布模式使用技能规定的 `ingest` 及关联参数。以后需要分享已有本地报告时，由用户登录后使用 `lh acceptance publish <acceptanceDir> --json`，不重跑产品。这里只复用 CLI，不维护另一套报告 schema 或自行编写 `report.html`。

在最终交付前完成以下收尾：

- 退出本轮启动的 Windows 应用，或停止本轮拥有的 Android 应用会话；不要结束用户原有实例、模拟器或共享 ADB 服务。
- 关闭本轮打开的浏览器会话与资源守卫（如有），记录资源限制导致的未完成项。仅撤销本轮可归属的临时改动，不用整份旧配置覆盖用户后续修改。
- 保留证据与诊断信息，报告临时文件和设备捕获文件的清理状态；不要删除失败证据以制造通过结果。
- 交付实际命令返回的验收地址或本地报告链接，并说明覆盖情况。本地报告说明页面中的 **Save reviews** 用于保存审核决定；不猜测地址，也不把成功渲染当成产品通过。

新发现写入项目的 [common-mistakes.md](common-mistakes.md) 或 [probe-mock-patterns.md](probe-mock-patterns.md)，注明源码依据或真实轮次。运行现实与适配文档不符时修正文档，不静默绕过。
